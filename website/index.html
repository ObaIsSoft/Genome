The Problem with LLM Designs

Layer 1 Concept

Every AI-generated website looks identical: an Inter font family paired with generic blue-purple gradients, generic rounded-xl card classes arranged in a boring 3-column grid, and a parallax scroll that makes you dizzy.

This isn't a design choice — it's a failure of constraints. Large Language Models (LLMs) default to "safe" average patterns because they lack structured guardrails forcing aesthetic consistency and visual courage.

The Genome Solution

Genome introduces a **Four-Layer SHA-256 Hash Chain** that deterministically guides both AI coding agents and human designers:

L0

CreatorGenome

16-chromosome latent DNA encoding a simulated designer persona (cultural vector, chaos tolerance, temporal era, authorial voice).

L0.8

ComponentTokenMap

Derived CSS tokens for custom elements. Computes multi-shadow stacks, exact curve coordinates, stroke widths entirely from math.

L1

DesignGenome

32 chromosomes defining global design logic: edge styles, color system boundaries, typography, motion curves, grids, and header strategy.

L2-L3

Ecosystem & Civilization

Architectural layout guidelines (microbial/flora/fauna composition contracts) and software architecture patterns (state management, routing).

💡
Determinism Guarantee: The entire downstream genome chain is fully deterministic. Given the same seed and design intent, it will produce the exact same hashes, tokens, and CSS properties forever.

Quick Installation

Terminal CLI

The Genome MCP engine can be installed globally via npm or cloned and built directly from the source repository.

1. Standard Global Install

zsh — global install 
npm install -g genome-mcp

2. Clone and Build from Source

If you want to contribute, test offline scripts, or run local benchmarks, clone the repository and build:

zsh — build local 
git clone https://github.com/ObaIsSoft/genome.git
cd genome
npm install
npm run build

3. Configure Environment Keys

Configure **any one** of the supported API providers inside a .env file in your project or exports. The engine auto-detects whichever is active:

IDE Integration & mcp.json Configuration

Setup Configuration

To enable coding assistants (like Cursor, Claude Code, Windsurf, or Claude Desktop) to invoke the 12 design tools automatically, add the server setup config block.

Cursor Configuration

Create a file at .cursor/mcp.json in your project root to activate the server locally:

mcp.json 
{
  "mcpServers": {
    "genome": {
      "command": "node",
      "args": ["/absolute/path/to/genome/dist/src/server.js"],
      "env": {
        "GROQ_API_KEY": "gsk_your_key_here"
      }
    }
  }
}

Claude Desktop Configuration

Edit your global claude_desktop_config.json under:
~/Library/Application Support/Claude/claude_desktop_config.json (MacOS)

Detailed Tool Reference

API Reference

generate_design_genome

Sequences the 32 L1 chromosomes representing structural spacing,Display typeface, Body typeface, Color Primary (hue/hex/dark mode), Surface Temperature stack, edges, and motion.

Key Arguments:
  • intent (string, required): Natural language description of product features and visual goal.
  • seed (string, required): Determines hashing seed.
  • font_provider (string, optional): One of "google", "bunny", "fontshare", or "none".

generate_component_tokens

Outputs exact, continuous CSS tokens derived for individual component names and descriptions based on latent-space coordinate calculations.

Key Arguments:
  • genome (object, required): The complete L1 Design Genome.
  • component_specs (array of objects, optional): Specific element descriptions (e.g. {"name": "nav-sidebar", "description": "dense panel"}).

validate_design

Evaluates your code against active genome constraints. Calculates a slop score (aiming for 0.0) based on detected slop patterns and verifies chromosome utilization.

Key Arguments:
  • genome (object, required): The core design genome structure.
  • css (string, required): Raw implemented style strings.
  • html (string, optional): Raw markup.

When to Use Genome MCP

Usage Guideline
✅ Ideal For
  • Greenfield Projects: Creating new web applications, tools, and dashboards completely from scratch without default bootstrap slop.
  • High Aesthetic Integrity: Portals, developer documentation, artistic showcases, or interfaces needing unique identity.
  • AI Agent Orchestration: Guarding AI coding assistants from writing generic, repetitive layouts.
❌ Not Suited For
  • Legacy Systems: Adding components into heavily pre-styled Bootstrap or corporate legacy stylesheets.
  • Fixed Brand Strictness: Projects where a strict brand book already mandates exact colors, margins, and typographies down to the pixel.
  • Zero-JS Static: Sites unable to handle CSS custom properties (IE11/legacy environments).
